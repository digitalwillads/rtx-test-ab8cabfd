Speed

It writes 195 tokens a second for one person, and 402 a second in total for eight people at once.

A token is about three quarters of a word. When more people share the box, each one sees words appear more slowly, but the box gets more done in total.

Power and memory decide the parts list

We logged every card's watts once a second during the tests, and the memory the running model held.

About 245 watts per card while writing

Writing words is limited by memory speed, not by raw compute, so the cards ran far below their limit. The peak was 285 watts on a card capped at 450.

So a Max-Q card, capped at 300 watts, writes just as fast.

About 390 watts per card while reading a long prompt

Reading a 100,000-token prompt is the heavy part, and each card drew up to 398 watts for those ten seconds.

So a Max-Q card would read long prompts somewhat more slowly.

220 GiB of the computer's memory

The model is too big for two cards alone. A third of its experts and its lookup tables live in the computer's memory, locked in place so that the cards can read them directly.

So the host needs 384 GB. With 256 GB, the computer would run out.

Two cards, no fast link between them

The cards share the work over the normal PCIe slots, with no NVLink bridge. The recipe is built for exactly that, so a plain workstation board is enough.

For Jacob: how these were measured

The server is diffbot's 2-card recipe for DeepSeek-V4.1-Flash-1017 (Hugging Face diffbot/DeepSeek-V4.1-Flash-EXL3-3bpw-2x-RTX-PRO-6000, revision 451f7dc) with its defaults: vLLM at tensor-parallel 2, EXL3 3-bit routed experts, 5,296 experts in pinned host RAM with a 512-slot VRAM cache, DSpark speculative decoding with 5 draft tokens, a 1M-token window, and an fp8 KV cache.

The speed curve is the recipe's own bench/codeconc.py: each stream asks for a complete program in Python, with thinking off, temperature 0 and up to 1,536 output tokens. The long prompt is the recipe's needle-test.py 6300, cold, at 100,834 prompt tokens.
