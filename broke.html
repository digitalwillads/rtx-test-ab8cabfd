What broke

Sixteen things went wrong during the test, and 13 of them now have a check in the kit.

Two came from outside, and fourteen were mistakes in our own scripts. None came from the model or the cards. The worst one cost 57 minutes of a billing box that did nothing.

From outside

Two surprises from the services we rented, not from our code.

Outside

The recipe's server image had been deleted

The recipe names a vLLM test build by its tag, and Docker Hub had already removed that tag. The image was still there under its fixed fingerprint, so we rented again with the fingerprint.

Now the rent script checks that the image exists before it rents a box.

Outside

Vast keys did nothing until a two-factor login

Both API keys Will made were refused for every action until the account logged in with a two-factor code. Vast emailed the code to Will, so the script read it from his inbox and logged in.

Now the kit has a login step. This one has no automatic check.

In our own scripts

Fourteen mistakes, most of them in the scripts that watched and graded the test.

Ours

The watcher waited 57 minutes on a dead setup

The watcher started a few seconds after setup had already died. It looked for the setup process, found none, and then waited for a log line that could never come.

Now every run writes a final exit line, even when it crashes, and watchers wait for that line.

Ours

The download tool read our patterns as file names

We gave the Hugging Face download tool several patterns after one flag. It took the extra ones as file names, fetched the wrong files, and setup died for lack of the recipe's scripts.

Now each pattern has its own flag, and setup stops at once when the recipe files are missing.

Ours

The "plain" Opus runs read Will's personal instructions

Claude Code reads an instruction file from every parent folder, even with empty settings, so our first Opus baseline ran with Will's own rules. We proved it by asking the model which font those rules ban.

Now every run happens in a fresh folder outside the home folder, and a guard refuses any folder with an instruction file above it. We threw away that $5.27 baseline.

Ours

The fake Barbara crashed on every Opus run

On the Mac we passed a relative results folder. The fake server runs inside each task's own folder, so it could not open its log and died on the first call, and Opus scored 0 of 3 for our mistake.

Now the folder is made absolute, the server checks its log when it starts, and the grader says when the server never ran.

Ours

Our own setting broke the first server start

The recipe passes every setting whose name starts with DS41 to the server without quotes. We had named one of ours that way, and the spaces in it split into stray words.

Now a test checks that the kit sets nothing with the recipe's prefixes.

Ours

A warm server was reported as failed

The script waited for a "warm" line in the server's log. Finding it closed the stream early, and the shell's strict setting counted that as a failure, even though the server was fine.

Now a tested wait function ignores that.

Ours

A watcher read an older run's ending

All runs shared one log, so a new watcher found the exit line of an earlier failed start and reported a failure that was not real.

Now each run writes its own fresh log.

Ours

The first speed test measured zero

The recipe's test script adds its own path to the address we give it, so the address had to end in /v1. Without that, every request hit a missing page and the test reported zero tokens.

Now the speed test fails loudly when it measures zero tokens.

Ours

The grader rejected a correct answer

DeepSeek reported a 44.23% rise in spend, which is exact, but the grader only allowed one decimal place.

Now the grader takes any decimals, and its self-check includes that real answer.

Ours

A package name looked like an error

While the box loaded, Vast's status listed software packages, and one is named liberror-perl. Our error check matched the letters "rror" and stopped the rent script.

Now the check matches only the shapes of real Docker errors.

Ours

Destroy asked "are you sure?" and quietly said no

The Vast tool asks for a yes before it destroys a box. With nobody at the keyboard it took silence as a no, so the six-hour safety timer would never have destroyed anything.

Now destroy answers yes, then checks that the box is really gone.

Ours

The SSD check said yes to a mode that was not built

Setup reported that the memory-saving SSD mode was available, because it found the mode's helper files. The patch was never applied, and it reads a different number format than this model pack.

Now the check looks for the applied patch inside the server code.

Ours

The key helper cut two characters out of the API key

The small script that hands Claude Code its API key used a character escape that the Mac's version of the tool does not support, so it deleted every x, 2 and 7 in the key.

Fixed in the helper. This one has no automatic check.

Ours

Hidden Mac files rode along to the box

Copying the kit from the Mac added hidden macOS files next to every file. DeepSeek noticed them in one task and correctly ignored them.

Now the copy leaves them out. This one has no automatic check.

For Jacob: the checks and where they live

Everything is in ~/Desktop/projects/gpu-box-test, a local git repository. Each check was written from the real case and fails without its fix.

Two more lessons for anyone running this again. On this Mac, grep is ugrep, which reads a $ in the middle of a pattern as an end-of-line anchor. And the Vast session key from the two-factor login cannot use the single-instance route, so the kit reads a box's status from show instances.
